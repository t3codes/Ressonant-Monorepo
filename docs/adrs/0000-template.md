# Título

Esses documentos têm nomes que são frases nominais curtas. Por exemplo, "ADR 1: Implantação no Django 3.0" ou "ADR 9: LDAP para integração multitenant".

## Contexto

Esta seção descreve as forças em jogo, incluindo as tecnológicas, políticas, sociais e locais do projeto.
Essas forças provavelmente estão em tensão e devem ser mencionadas como tal.
A linguagem desta seção é neutra em relação a valores.
Ela simplesmente descreve os fatos.

## Decisão

Esta seção descreve nossa resposta a essas forças. Ela é apresentada em frases completas, na voz ativa. "Nós iremos…"

## Consequências

Esta seção descreve o contexto resultante após a aplicação da decisão.
Todas as consequências devem ser listadas aqui, não apenas as "positivas".
Uma determinada decisão pode ter consequências positivas, negativas e neutras, mas todas elas afetam a equipe e o projeto no futuro.

---

O documento completo deve ter uma ou duas páginas.
Redigiremos cada ADR como se fosse uma conversa com um futuro desenvolvedor.
Isso exige um bom estilo de escrita, com frases completas organizadas em parágrafos.
Marcadores são aceitáveis apenas para fins de estilo visual, não como desculpa para escrever frases fragmentadas.

Em casos onde a ADR não tem mais efeito, adicionar um -DEPRECATED, no final do nome do arquivo, e adicionar a seguinte
observação abaixo do título se fizer sentido:

```markdown
ADR substituída por: 0999-nova-adr.md
```
